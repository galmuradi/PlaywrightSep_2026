### package-lock.json


### playwright.config.js

Path:

```text
C:\Play_Test\playwright.config.js
```

This is the main Playwright configuration file.

Important settings:

```js
testDir: './tests'
```

This tells Playwright to look for tests inside the `tests` folder.

```js
fullyParallel: true
```

This allows tests to run in parallel.

```js
retries: process.env.CI ? 2 : 0
```

This means:

- Locally: no retries.
- In CI: retry failed tests 2 times.

```js
reporter: [
  ['html'],
  ['allure-playwright'],
  ['html', { outputFolder: 'playwright-report', open: 'never' }],
  ['junit', { outputFile: 'junit-reporter.xml' }]
]
```

This creates:

- Playwright HTML report.
- Allure report data.
- JUnit XML report for CI tools.

```js
use: {
  screenshot: 'only-on-failure',
  trace: 'retain-on-failure'
}
```

This saves screenshots and traces only when tests fail.

What this teaches:

- How to configure Playwright.
- How to generate reports.
- How to set CI-specific behavior.

## 3. Pages Folder

### Pages/LoginPage.js

Path:

```text
C:\Play_Test\Pages\LoginPage.js
```

This file uses the Page Object Model pattern.

It stores login page locators:

```js
this.username = page.getByPlaceholder('Username');
this.password = page.getByPlaceholder('Password');
this.loginBtn = page.getByRole('button', { name: 'Login', exact: true });
```

It also has a reusable login method:

```js
async loginToApplication(username, password) {
  await this.username.fill(username);
  await this.password.fill(password);
  await this.loginBtn.click();
}
```

What this teaches:

- How to avoid repeating login code in every test.
- How to create reusable page classes.
- How to separate page actions from test logic.

Used by:

```text
tests\LoginApplication.spec.js
```

## 13. Recommended Cleanup

These improvements would make the project easier to maintain:

- Rename `Alret` to `Alert`.
- Rename `Tages.spec.js` to `Tags.spec.js`.
- Rename `Locater` and `Locaters` to `Locator` and `Locators`.
- Use either CommonJS or ES module imports consistently.
- Add scripts to `package.json`, for example:

```json
"scripts": {
  "test": "playwright test",
  "test:headed": "playwright test --headed",
  "report": "playwright show-report"
}
```

- Make the JUnit file name match between `playwright.config.js` and Azure pipeline YAML.
- Remove or archive duplicate files under `PlayWright Script` if they are not needed.
- Avoid committing generated folders such as `node_modules`, `playwright-report`, `allure-report`, `allure-results`, and `test-results`.
